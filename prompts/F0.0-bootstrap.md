# Prompt F0.0 — Bootstrap del repositorio

Eres el agente de código de Galaxystem. Esta es la subfase F0.0: preparar el repositorio para que todo el trabajo siguiente se haga con verificación automática desde el primer commit.

## Lee primero

- `CLAUDE.md` completo.
- `README.md`.
- `docs/F0-diseno.md` §8 (crates) y §9 (dependencias).
- `docs/F0-validacion.md` §V3, fila F0.0.

**Ya existen y no debes reescribir:** `README.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `docs/`, `prompts/` y `templates/`.

## Objetivo

Workspace de Cargo con los crates vacíos del núcleo, licencias, herramientas de calidad y CI, compilando para x86_64 y aarch64.

## Incluye

1. **Repositorio git** (si no existe) con un `.gitignore` para Rust.
2. **Workspace** en la raíz con `resolver = "3"`, edición 2024, `rust-version = "1.85"` y perfil release:
   ```toml
   [profile.release]
   lto = "fat"
   codegen-units = 1
   panic = "abort"
   debug = "line-tables-only"
   ```
   Agrega también un perfil `bench` que herede de release con `debug = true`, para perfilar.
3. **Crates en `nucleo/`**, todos `license = "MPL-2.0"`, cada uno con un `lib.rs` (o `main.rs`) mínimo, el aviso MPL y los atributos de `CLAUDE.md`: `gx-arena`, `gx-scan`, `gx-snap`, `gx-search`, `gx-synth`, `gx-bench`, `gx-cli` (binario `gx`), `gx-sized` (binario).
4. **Directorio `app/`** solo con un `README.md` que diga que la app GPL llega en la F1. No es miembro del workspace todavía.
5. **Licencias:**
   - `LICENSE-MPL-2.0` con el texto oficial completo de https://www.mozilla.org/en-US/MPL/2.0/;
   - `LICENSE-GPL-3.0` con el texto oficial completo de https://www.gnu.org/licenses/gpl-3.0.txt.
   
   Si no tienes acceso a la red, deja el archivo con una línea que indique de dónde copiarlo y repórtalo en "Pasos que requieren a Ricardo".
6. **Calidad:**
   - `rustfmt.toml` mínimo;
   - `clippy.toml` con `msrv = "1.85"`;
   - `deny.toml` para `cargo-deny` que permita solo MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, Unicode-3.0 y MPL-2.0, que prohíba dependencias de fuentes no registradas, y que avise de duplicados.
7. **CI** en `.github/workflows/ci.yml`, sobre `ubuntu-latest`:
   - `fmt`, `clippy -D warnings`, `test`;
   - `cargo deny check`;
   - compilación cruzada para `aarch64-unknown-linux-gnu` (con `gcc-aarch64-linux-gnu` y la configuración de linker en `.cargo/config.toml`);
   - un job que ejecute `cargo test` para aarch64 con `qemu-user`, con `continue-on-error` hasta la F0.1.
8. **`bench/queries.txt`** vacío, con un comentario que diga que se llena en la F0.4.

## No incluye

Ninguna lógica de escaneo, arena ni generador. Los crates quedan vacíos salvo los tipos `NodeId` y `Flags` en `gx-arena` (solo la definición, con las constantes de bits de `F0-diseno.md` §1.4) y una prueba unitaria trivial por crate para que `cargo test` ejecute algo.

## Procedimiento

1. Responde con un **plan breve**: lista de archivos que vas a crear y cualquier duda. **Espera "aprobado".**
2. Implementa.
3. Ejecuta todos los comandos de verificación de `CLAUDE.md`. Si no tienes el toolchain de aarch64, instálalo con `rustup target add` y el linker con el gestor de paquetes. Si no puedes, repórtalo.
4. Haz commits firmados con DCO, siguiendo Conventional Commits.
5. Entrega el reporte con `templates/reporte-subfase.md` y **detente**.
